## 1、图谱里有什么

- **17 个架构维度**：系统概念介绍、MTK 平台介绍、MCU 与 SOC 分工、Android／HMI 与显示、应用与 Framework、HAL／驱动／硬件抽象、Camera／环视与舱内感知、音频架构、TBox、CAN 与以太网、SOA 架构、虚拟化通讯、电源管理、升级与信息安全、时间同步、性能与资源、诊断与证据。
- **三级星群和四级下钻**：首次进入显示智能座舱、17 个二级中心、全部三级星点及其连线。三级文字在空闲时隐藏，悬停、搜索、选中或进入当前链路时出现；点击三级节点后继续展开四级知识点。
- **一份知识，多处归属**：每个三级节点只有一个实体和一条主要层级路径；跨域能力通过次要归属线同时连接多个二级维度。当前共有 42 个多归属三级节点，页面不会复制同名知识点。
- **完整学习映射**：48 个 Day、26 个 Week、21 个 T12T 技能和 299 份资料已经分散映射到实际知识链。原始资料不再作为首页的平行主分支，完整文件目录仍保留独立检索入口。
- **知识金字塔**：所有公开节点保留唯一主父级，并以智能座舱 → 架构维度 → 知识链 → 知识点 → 机制／状态 → 观测／证据逐层下钻。控制、数据、电源、状态和诊断关系作为横向技术网络显示。
- **链路内案件与 TPM**：脱敏日志案例按症状组映射到适用链路；触发方、首轮牵头、直接失效责任、修复方、验证方和关闭判据放在具体知识链中，不单列成脱离架构的 TPM 分支。
- **电源细分链路**：车辆输入与策略、MCU 握手、真实供电、Guest／Host／Hypervisor 准备、Suspend、唤醒源、TBox／RTC、业务恢复和静态电流证据保持为可继续下钻的具体知识点。
- **架构章节和课程正文**：连接原站的中文版架构文章、Day 课程和 Week 复盘。
- **语义知识层**：包含 111 个平台、域、组件、接口、状态、流程、观测点和失效模式实体，以及 72 条结构化技术关系。106 个实体已有职责、输入、机制、输出、观测点与证据边界；5 个显示 L5 节点明确标记为“资料尚未吸收”，不会自动生成结论。
- **MT8668 / MT8676 平台关系**：共享模块同时挂接两个平台，平台专属模块保留单平台范围；两个平台通过带双份资料证据的共同族关系直接相连。
- **完整导航桥接**：座舱知识入口经主题连接知识域，知识域连接实体，平台连接适用实体，299 份来源连接其 `knowledgeIds`，避免出现无归属节点。
- **控制、数据、电源、状态和诊断路径**：五类连线分色显示，可单独筛选。每条技术关系说明为什么有关、输入、交接点、输出和验证方法。
- **证据层**：默认隐藏；选中知识点后点击“展开所选节点证据”，只显示相关页码证据和原始资料，避免 299 个来源节点淹没主图。

车型、SoC、软硬件版本与真实接口仍须结合相应架构资料和本次项目证据核验；课程发布也不代表学习者已完成或掌握。

## 2、如何使用

1. 鼠标悬停星点可看到放大的标题、简短预览和突出显示的关联线；移开后恢复。点击星点后，它会平滑移动到画面中心；点击关联节点可以继续切换中心。
2. 左侧可按别名搜索，按 MT8668/MT8676 平台或控制、数据、电源、状态、诊断路径筛选。点击“电源与生命周期”可查看 MCU、Yocto、Hypervisor、Guest、Kernel、ATF、SPM、PMIC 和 MT6363 的分层关系。
3. 银河旋转时只显示转到镜头前方的一组节点名称；其他节点保留为发光星点，悬停、搜索或点击时立即显示完整名称。拖动会产生惯性，滚轮或右下角按钮可缩放；点击空白处或重置按钮返回总览。
4. 点击节点会打开“专题阅读”面板：依次显示面包屑、主要／交叉架构归属、本层职责、直接子层、课程与技能、正常技术链、脱敏案例与 TPM、验证方法、资料映射理由以及引用证据。点击子层可继续下钻；点击面包屑可返回上层。
5. 引用只沿所选节点的直接技术关系与一层相邻技术链收集，不会通过平台、目录或其他分类扩散到无关专题。公开 PDF 与文章可在页面内加载或打开原文，PDF 提供下载入口；当前专题也可导出包含关系理由和引用链的 Markdown 文件。
6. 未选中节点且闲置约 10 秒后，银河以三轴轻微漂移的方式缓慢巡航。可手动暂停，系统“减少动态效果”设置也会生效。
7. 详情面板显示运行域、平台范围、证据状态、来源、页码和下载链接。`documented_reference` 表示原文页级依据，`inferred_mapping` 表示映射推断，`conflicting` 表示版本冲突，`indexed` / `source_register` 只表示资料已登记；它们都不能替代当前车型和版本核验。

## 3、与原仓库的联动

数据源是原仓库公开发布的 `docs/index.html`、`docs/architecture/`、`docs/lessons/` 和 `content/learning-progress.json`。本仓库的 [GitHub Actions 更新流程](.github/workflows/update-graph.yml)会在北京时间 **20:45** 和次日 **09:35** 检查原仓库，重建并验证 `docs/graph.json`；索引有变化才提交，随后由 GitHub Pages 发布。也可在 Actions 页面手动运行该流程。定时任务可能受 GitHub 排队影响，因此更新不是实时的。

同步只读取这些公开页面和学习进度文件。原始资料目录由人工维护；自动更新不会覆盖它。本仓库不采集或上传私有日志、异常包、账号信息和内部项目证据。

知识实体和证据位于 [`content/domain-packs`](content/domain-packs)，299 份资料的公开处理登记位于 [`content/source-register.json`](content/source-register.json)。原始资料分类由 [`content/raw-taxonomy.json`](content/raw-taxonomy.json)维护；4 份大文件位于 [GitHub Release](https://github.com/qiantao18817568425-art/Cockpit_Knowledge_Galaxy/releases/tag/raw-sources-2026-10-16)。状态名、供电策略、跨域握手和唤醒线路是否适用于某辆车，仍须按车型、硬件、软件版本及实车证据确认。

本地重建与检查（Node.js 即可，无需安装前端依赖）：

```text
node scripts/build-graph.mjs --source <Architecture_Learning- 的本地路径>
node --check docs/app.js
node --check docs/graph-model.js
node --check docs/space-scene.js
node --test tests/*.test.mjs
node scripts/serve.mjs
```

本地网站默认地址为 `http://127.0.0.1:4173/`。当前生成结果为 719 个节点、1,939 条边；17 个二级维度、45 条三级知识链、499 个直接四级节点、42 个多归属三级节点。资料映射中的 `indexed` 或 `needs_review` 只表示已归类或待复核；只有明确页码和版本范围的记录才可作为页级技术依据。
