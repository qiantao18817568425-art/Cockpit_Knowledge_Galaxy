组合升级与单独 SoC 升级的两个断点

组合升级中，MCU 记录擦除成功，随后未观察到期望的数据阶段推进。单独 SoC 升级中，宿主完成关机重启，Bootloader 等待升级进入事件，随后转正常启动。两个断点各有证据，升级应用触发链和 SoC 掉电责任仍待确认。

控制、数据与电源边界

  • 组合升级控制链：升级编排 → MCU 擦除确认 → 数据阶段超时/复位。擦除确认只覆盖擦除里程碑。MCU 侧未观察到写入，发送方是否真正发包及链路何处丢失需要双端序列证据。
  • 单独升级控制链：Host 关机 → Bootloader 等待 → 正常启动。进入等待、真正建立升级会话、分区写入与版本生效分别验收。
  • 电源链：报告结合复位记录和后续启动原因/uptime 回推掉电冷启。早期 SoC 同窗缺口使复位发起者、掉电联动路径和进度停滞先因仍有不确定性。

证据索引

原报告 §2–6 记录 MCU 串口、SoC 串口及记录窗口。MCU 侧的擦除成功、复位请求与 SPI 超时可分层观察。SoC 后续 Host shutdown、Bootloader wait 和正常启动各自有时序证据。随后线刷再升级成功只验证那次版本组合和路径。报告中的交接时间、枚举值与超时参数仅适用该样本。

责任与关闭判据

升级编排牵头，MCU/跨域接口双方同步记录各事务发送、接收、进度、复位请求与发起者。Bootloader/USB 负责人记录进入事件、枚举和实际升级会话。电源域核实复位与供电时序。系统测试覆盖组合升级、单独升级、缺数据/丢事件、掉电恢复、混合版本与相邻业务。以同一组合完整写入/激活、读回版本一致、异常后恢复至明确终态作为验收。修复版本及回归报告待补。
