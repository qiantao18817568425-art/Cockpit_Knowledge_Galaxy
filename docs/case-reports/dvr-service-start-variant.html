板级配置导致 DVR 服务启动分叉

两份 MT8668 Android Guest 日志报告显示系统构建一致，板级配置读值不同。板级识别 → 只读启动属性 → init 属性条件 → 服务启动，构成可复核的控制链。两边业务开关一致，服务启动发生在用户操作前。

对照证据

  • 报告 §2–4：DVR 配置分支未命中 HIK 服务启动条件，客户端达到重连上限后退出。
  • 报告 §2–4：AVM 配置分支在启动完成后命中 init 条件，HIK 服务启动，客户端随后连上。
  • 报告 §5–7：现有材料可解释为何两样本进入不同服务分支。是否同一物理设备及当前板型映射仍待核实。服务分叉是故障暴露条件，介质方法为何拒绝仍须独立分析。见 介质回调异常主报告。

责任与关闭判据

测试确认两样本的设备归属和硬件版本。BSP/硬件按目标版本核对板型识别、映射和跨冷启动稳定性。系统集成核对属性、init 条件、服务发布和连接结果。若为同一设备且识别发生漂移，应补启动采样及硬件侧证据。若为不同变体，应各自符合产品定义，并独立验证可连分支的介质回调及容错。
