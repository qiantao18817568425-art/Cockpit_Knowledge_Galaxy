DVR 介质回调失败与共享进程连锁影响

报告范围为 MT8668 的 Android Guest 对照样本。首个可证实断点是 DVR 服务连接成功后，介质状态回调注册收到未捕获的 SecurityException，终止了同时承载其他业务的客户端共享进程。重复拉起与注册使故障循环。直接失效置信度高，服务端抛出异常的原因仍待核验。

正常链与故障传播

控制链：客户端绑定 DVR 服务 → 服务连接 → 按项注册回调 → 接收介质状态。前序回调注册成功只覆盖对应事务。出错后，Binder 死亡回调和新 PID 拉起说明共享进程重建。报告未显示 Guest、VM、Host、SoC 或 MCU 重启证据。数据链应分别检查介质状态、蓝牙适配器、亮度写入/回读与音频输出。此材料未建立物理摄像头、屏幕、电源或功放故障链。

证据与界限

  • 报告 §4、§6、§8：同一进程实例完成连接和前序注册，介质注册抛异常。客户端退出与重启链可对齐。
  • 报告 §5：蓝牙设置初始化超时与共享服务不可用存在关联。亮度回弹和音频跳变需分别补写后回读、焦点/路由与实际播放的同窗记录。
  • 对照样本只缓存监听器并有限重连，未进入同一远端方法。对照条件见 DVR 服务启动分叉。

责任与关闭判据

系统集成牵头，DVR 服务方核对双方接口版本、事务及方法级鉴权、配置加载和初始化。客户端负责隔离可选回调失败、限频退避和死亡恢复。系统测试须在同一版本组合上验证正常介质回调、服务早到/晚到、重启、异常注入和退避上限，确认共享进程持续可用，并对蓝牙设置、通话、音频、手动/自动亮度及录制做回归。服务端拒绝原因、补丁版本及实测结果待补。
