# 桌面端 WebGL 知识星图整体替换

## 意图

用户认为上一版中心星图仍缺少真实三维动态质感，要求全部替换。桌面端首页应成为可旋转、推进、聚焦的 EVE 风格星区，知识阅读和资料证据仍可直接使用。

## 设计边界

- 默认桌面视图使用仓库已内置的 Three.js 180 和 WebGL；浏览器不支持 WebGL 或三维场景启动失败时显示现有 Canvas 星图。
- 星区坐标、可见层级和高亮路径沿用 `space-scene.js` 的确定性真实图谱模型。装饰星尘与知识节点分层，装饰元素不可点击。
- 左侧控制区、场景信息、星区标签、右侧阅读器统一为深色航图界面。新的视觉工作只覆盖桌面宽屏；窄屏保留既有布局。
- 原始资料目录与知识覆盖报告同步使用相同的桌面航图配色与排版，不改变文档数据和链接。
- 真实节点用深度、光晕、颜色和大小区分层级。普通关系线低亮度；悬停突出相邻节点；点击后沿真实父级链显示路线及移动光点。
- 进场镜头、拖拽旋转与惯性、滚轮平滑缩放、鼠标微视差、巡航和选中聚焦在 WebGL 场景中完成。减少动态效果偏好关闭自动运动和路径光点。
- 保留当前 `app.js` 的图谱数据加载、搜索、筛选、阅读器、证据与下载逻辑，通过小型桥接事件同步 WebGL 场景。Canvas 渲染器只在回退模式启动。

## 实现方式选择

1. 直接启用仓库中的旧 Three.js 原型：代码量较少，但仍是空心球壳，关联旧阅读器，无法满足这次的中心星区和资料体验。
2. **新建 WebGL 星图区并桥接当前阅读器**：复用已验证的星区与知识模型，三维画面和桌面外观整体替换，同时保持数据功能。采用此方式。
3. 重写所有图谱与阅读器：会重复已有证据与阅读逻辑，增加资料链接和筛选回归风险。

## 验收

- WebGL 可用时首页确实创建 `THREE.WebGLRenderer`，并显示可旋转的三维节点、线、星尘与镜头运动。
- 740 个真实节点都有位置；默认交互节点数与现有语义缩放模型一致；路线仅由真实父级边产生。
- 搜索、平台/关系筛选、主题导航、点击节点、阅读器、证据、资料预览和下载继续工作。
- WebGL 不可用或初始化失败时自动进入 Canvas；上下文丢失时给出明确的重载切换按钮。窗口从桌面宽度缩窄时，已运行的三维画布仍保持可见。
- 定向模型与接线测试通过；可执行的全套测试通过或明确记录与稀疏检出相关的基线缺口。

## 已知验收限制

当前环境的浏览器 origin 策略此前拒绝本地和线上预览。交付前可执行静态与模型测试；真实浏览器画面和交互结果需在草稿 PR 中继续验收，不能以生成的概念图冒充页面截图。
